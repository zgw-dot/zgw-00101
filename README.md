# 培训排课与出勤管理系统

离线桌面工具，基于 Python + PySide6 + SQLite 开发。

## 功能特性

### 核心功能
- 📅 **课程日历**：日历视图展示所有已发布课程，点击日期查看当日课程
- 📚 **课程管理**：创建、编辑、发布、删除课程，支持草稿/已发布状态
- 👨‍🏫 **讲师场地**：课程信息包含讲师、场地、时间、容量等完整信息
- 👥 **报名管理**：学员报名，容量控制，超容量自动拦截并记录异常
- 📥 **批量导入**：CSV 批量导入学员报名，逐行校验，支持导入结果导出
- 🔄 **调课申请**：学员可申请调到同主题其他场次，管理员审核
- ⚙️ **批量调整**：课程详情页可批量取消、批量改状态、批量调课，操作前确认摘要
- ↩️ **撤销功能**：当前会话内可撤销上次批量操作，自动恢复报名状态和容量
- 📊 **操作追踪**：批量操作记录完整日志，支持逐条失败原因追溯和结果导出
- ✍️ **签到管理**：课程进行中签到，重复签到自动拦截
- 📝 **补签审核**：缺勤学员申请补签，管理员审核后生效
- 🎓 **结业证书**：课程结束后按出勤记录批量生成结业证书，支持补发、作废
- ⚠️ **异常日志**：记录所有违规操作（超容量、重复签到、截止后调课等）
- 📊 **历史记录**：查询所有课程历史，支持按日期范围筛选
- 📤 **CSV 导出**：导出生勤表、异常日志、历史记录汇总、批量导入结果、结业证书

### 业务规则与失败拦截

| 拦截场景 | 触发条件 | 处理方式 |
|---------|---------|---------|
| 结束早于开始 | 课程结束时间 ≤ 开始时间 | 提示"课程结束时间必须晚于开始时间" |
| 超容量报名 | 报名人数 ≥ 课程容量 | 提示容量已满，记录异常日志 |
| 报名截止后调课 | 调课申请时间 > 原课程报名截止时间 | 拒绝调课，记录异常日志 |
| 重复签到 | 同一学员在同一课程重复签到 | 拒绝签到，记录异常日志 |
| 未审核补签生效 | 补签申请未通过审核直接生效 | 审核流程强制拦截，必须管理员审核 |
| 调非同主题课程 | 调课目标课程与原课程主题不同 | 提示"只能调到同主题的其他场次" |
| 未开始/已结束签到 | 签到时间不在课程进行时段 | 提示课程未开始或已结束 |
| 批量导入必填字段缺失 | CSV 行中姓名或工号为空 | 该行拦截，提示缺少必填字段，记录异常日志 |
| 批量导入重复工号 | 同一工号在课程中已存在 | 该行拦截，提示该学员已报名此课程，记录异常日志 |
| 批量导入容量不足 | 导入过程中课程容量已满 | 后续行拦截，提示容量已满，记录异常日志 |
| 批量导入未发布课程 | 导入目标课程未发布 | 所有行拦截，提示课程未发布，记录异常日志 |
| 批量导入格式错误 | CSV 缺少姓名或工号列 | 导入中断，提示缺少必填列 |
| 批量操作已取消报名 | 对已取消的报名执行批量操作 | 该条拦截，提示"已取消报名，无法操作"，记录异常日志 |
| 批量操作重复学员 | 批量调课时目标课程已有该学员 | 该条拦截，提示"该学员已报名目标课程"，记录异常日志 |
| 批量操作非同主题 | 批量调课目标课程与原课程主题不同 | 整条操作拦截，提示"只能调到同主题的其他场次" |
| 批量操作容量不足 | 批量调课目标课程容量不足 | 超出容量的记录拦截，提示"课程容量已满"，记录异常日志 |
| 批量操作未发布课程 | 对未发布的课程执行批量操作 | 整条操作拦截，提示"只能对已发布课程执行批量操作" |
| 撤销跨会话 | 程序重启后执行撤销 | 撤销不可用，提示"没有可撤销的操作"（会话边界保护） |

## 修复记录

### 问题：批量导入只有服务层，GUI 无入口

**根因分析**：前一版本实现了 `RegistrationService.batch_import_students()` 服务层方法和相关测试，但**未在 PySide6 GUI 中添加入口**。管理员无法通过桌面界面触发批量导入，只能通过代码调用服务层方法。

**最小改动修复**：
1. **GUI 入口**：在 `CourseDetailWidget` 工具栏添加橙色「批量导入报名」按钮（`ui/widgets.py` 第 293-296 行）
2. **结果展示**：新增 `BatchImportResultDialog` 对话框（`ui/dialogs.py` 第 498-597 行），展示成功/失败统计和逐行明细
3. **交互逻辑**：实现 `batch_import()` 方法（`ui/widgets.py` 第 461-491 行），串联文件选择器 → 服务调用 → 结果展示
4. **结果导出**：在结果对话框添加「导出结果」按钮，调用 `ExportService.export_import_result()`

**用户操作路径**：
1. 启动程序 → 课程管理 → 双击目标课程
2. 点击橙色「批量导入报名」按钮
3. 选择 CSV 文件 → 查看结果 → 可导出结果 CSV

### 问题：报名管理缺少批量调整能力

**根因分析**：前一版本仅支持单条报名操作，管理员需要对已发布课程的报名名单进行批量调整时，只能逐条操作，效率低下且缺少撤销机制。

**功能实现**：
1. **批量选择**：课程详情页报名表格增加复选框列，支持全选/取消全选，实时显示已选择人数
2. **批量操作**：
   - **批量取消**：将选中报名状态改为「已取消」，释放课程容量
   - **批量改状态**：将选中报名改为指定状态（已报名/已出勤/缺勤/已取消/已转出）
   - **批量调课**：将选中报名转移到同主题其他场次，自动校验容量和重复
3. **确认摘要**：操作前弹出确认对话框，显示操作类型、目标课程、警告信息和学员列表
4. **结果展示**：操作完成后显示成功数、失败数和逐条失败原因
5. **撤销功能**：会话内可撤销上次批量操作，自动恢复报名状态、容量占用和日志
6. **结果导出**：支持导出操作结果 CSV，包含原报名信息、目标课程、处理结果和失败原因

**用户操作路径**：
1. 启动程序 → 课程管理 → 双击目标课程（必须已发布）
2. 在「报名名单」标签页中勾选要操作的学员（或点击「全选」）
3. 点击对应批量操作按钮（红色「批量取消」、紫色「批量改状态」、蓝色「批量调课」）
4. 查看确认摘要 → 点击「确认执行」
5. 查看操作结果 → 可「撤销此操作」或「导出结果」

## 数据库表结构

- **courses**：课程表（标题、主题、讲师、场地、时间、容量、状态等）
- **students**：学员表（姓名、工号、部门、联系方式）
- **registrations**：报名表（关联课程与学员，含状态）
- **transfer_requests**：调课申请表（原课程、目标课程、审核状态）
- **attendances**：出勤表（签到时间、状态、补签信息）
- **exception_logs**：异常日志表（类型、描述、处理状态）
- **batch_operation_logs**：批量操作日志表（操作类型、源课程、目标课程、成功/失败数、是否撤销）
- **batch_operation_items**：批量操作明细表（关联批量日志、报名ID、学员ID、原状态、新状态、是否成功、失败原因、撤销数据）
- **certificates**：结业证书表（唯一编号、课程、学员、状态、发放日期、作废原因等）
- **certificate_batch_logs**：证书批量操作日志表（课程、操作类型、成功/失败数）
- **certificate_batch_items**：证书批量操作明细表（关联批量日志、学员ID、证书ID、是否成功、失败原因）

#### 步骤 1：创建并发布课程
1. 点击左侧菜单「课程管理」
2. 点击「新建课程」按钮

   - 标题：Python 基础培训（第二场）
   - 主题：Python 编程（与第一场相同）

   - 容量：2

1. 在「课程管理」中双击第一场课程进入详情

3. 填写学员信息：
   - 姓名：张三

4. 点击确定，提示报名成功
5. 继续报名：李四（E002）、王五（E003）

6. 查看「异常日志」，应该有一条「超容量报名」记录

#### 步骤 3：申请调课
1. 在第一场课程详情的「报名名单」中，点击张三的「调课」按钮

5. 点击「审核」，选择「通过」
6. 回到课程详情查看：
   - 第一场：张三已转出，只剩李四
   - 第二场：张三已转入

#### 步骤 4：签到与出勤
1. 调整系统时间到第一场课程进行时段（或修改课程时间到当前时段）

4. 再次输入 E002，提示「请勿重复签到」
5. 查看「异常日志」，有「重复签到」记录
6. 点击「一键标记缺勤」，将未签到的标记为缺勤

#### 步骤 5：补签审核
1. 在第一场课程详情的「出勤状态」中
2. 缺勤学员可以点击「申请补签」
3. 填写补签原因（至少5字），提交申请
4. 到「补签审核」页面，看到待审核的补签申请
5. 点击「审核」，可以通过或驳回（驳回必须填写原因）
6. 通过后回到课程详情，状态变为「已出勤（补签）」

#### 步骤 6：查看完整出勤状态
1. 进入任意课程详情
2. 切换到「出勤状态」标签页
3. 可以看到所有学员的完整出勤状态：
   - 已出勤 / 缺勤 / 未签到

### 4. 批量导入失败场景验证（GUI 操作）

#### 验证 1：缺少必填字段
1. CSV 中某行姓名或工号为空
2. 导入后该行被拦截，原因显示「缺少必填字段：姓名或工号不能为空」
3. 其他有效行正常导入，不回滚

#### 验证 2：重复工号
1. 同一工号在 CSV 中出现多次，或已在课程中存在
2. 重复的行被拦截，原因显示「该学员已报名此课程」
3. 首次出现的行正常导入

#### 验证 3：课程容量不足

## 常见问题

**Q: 数据库文件在哪里？**
A: 程序运行后在 `main.py` 同目录下自动生成 `training.db` 文件。

**Q: 如何重置数据？**
A: 关闭程序，删除 `training.db` 文件，重新启动即可。

**Q: 导出的 CSV 文件在哪里？**
A: 导出目录是程序目录下的 `exports/` 文件夹，文件名包含时间戳。

**Q: 为什么无法删除课程？**
A: 已有学员报名的课程不允许删除，请先处理报名记录。

**Q: 如何修改已发布课程的时间？**
A: 在「课程管理」中选中课程，点击「编辑」即可，但容量不能小于已报名人数。

**Q: 批量导入支持哪些 CSV 格式？**
A: 支持 UTF-8 编码的 CSV 文件，表头支持中文（姓名、工号、部门、联系方式）或英文（name、employee_id、department、phone）。其中姓名和工号为必填列。

**Q: 批量导入时一行数据错误会影响其他行吗？**
A: 不会。系统逐行处理，每行独立校验。某行失败只会拦截该行，其他有效行正常导入，不会整批回滚。

**Q: 如何查看批量导入的失败原因？**
A: 导入完成后会显示失败明细，包含原始行号、学员信息和具体失败原因。也可以导出导入结果 CSV 留档，或在「异常日志」中查看导入相关的异常记录。

**Q: 批量导入的学员数据会持久化吗？**
A: 是的。成功导入的报名记录、异常日志和课程容量占用都会写入 SQLite 数据库，关闭程序重开后数据保持一致。

**Q: 导出的批量导入结果 CSV 包含哪些内容？**
A: 包含导入统计信息（总/成功/失败数）、每行的原始行号、学员信息（姓名、工号、部门、联系方式）、处理结果（成功/失败）、失败原因（如有）和报名 ID（如成功）。

**Q: 批量操作支持哪些类型？**
A: 支持三种批量操作：
1. **批量取消**：将选中报名状态改为「已取消」，释放课程容量
2. **批量改状态**：将选中报名改为指定状态（已报名/已出勤/缺勤/已取消/已转出）
3. **批量调课**：将选中报名转移到同主题的其他场次

**Q: 批量操作可以对哪些课程执行？**
A: 只能对**已发布**的课程执行批量操作。草稿状态的课程不支持批量调整。

**Q: 批量调课有哪些限制？**
A: 批量调课有以下限制：
1. 目标课程必须与原课程**同主题**
2. 目标课程必须已发布
3. 不能重复报名（同一学员不能在目标课程中已存在）
4. 目标课程必须有足够容量（超出容量的记录会被拦截）
5. 已取消的报名不能调课

**Q: 批量操作中部分失败会影响其他记录吗？**
A: 不会。系统逐条处理，每条记录独立校验。某条记录失败只会拦截该条，其他有效记录正常执行，不会整批回滚。

**Q: 如何查看批量操作的失败原因？**
A: 操作完成后会弹出结果对话框，显示每条记录的处理结果和具体失败原因。也可以导出结果 CSV 留档，或在「异常日志」中查看批量操作相关的异常记录。

**Q: 撤销功能可以撤销哪些操作？**
A: 撤销功能只能撤销**当前会话内**最后一次成功的批量操作（包括批量取消、批量改状态、批量调课）。程序重启后，之前的操作无法撤销。

**Q: 撤销后数据会如何恢复？**
A: 撤销会自动恢复：
1. **报名状态**：批量取消/改状态会恢复原始状态
2. **容量占用**：调课撤销会恢复源课程容量，删除目标课程的新报名
3. **操作日志**：会记录撤销操作到异常日志
4. **批量操作状态**：对应的批量操作日志会标记为「已撤销」

**Q: 撤销功能的快捷键是什么？**
A: 主工具栏有「撤销上次批量操作」按钮，快捷键是 **Ctrl+Z**。只有当存在可撤销的操作时，按钮才可用。

**Q: 批量操作的日志会保留多久？**
A: 所有批量操作的日志（包括成功、失败和撤销记录）都会永久保存在 SQLite 数据库中，除非手动删除数据库文件。

**Q: 导出的批量操作结果 CSV 包含哪些内容？**
A: 根据操作类型不同略有差异，通用包含：
- 操作统计信息（总/成功/失败数）
- 原课程信息、目标课程信息（调课时）
- 每条记录的学员信息（工号、姓名、部门）
- 原状态、新状态
- 处理结果（成功/失败）
- 失败原因（如有）

## 10. 结业证书管理

### 10.1 功能概述

结业证书管理模块允许管理员在课程结束后，根据学员的出勤记录批量生成结业证书。支持单个学员的证书补发和作废操作。所有证书信息持久化存储到 SQLite 数据库，关闭重启后数据保持一致。

### 10.2 数据库表结构

#### 10.2.1 `certificates` 表（结业证书表）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | INTEGER PRIMARY KEY | 主键 |
| `certificate_no` | TEXT UNIQUE | 证书唯一编号 |
| `course_id` | INTEGER | 关联课程ID |
| `student_id` | INTEGER | 关联学员ID |
| `registration_id` | INTEGER | 关联报名ID |
| `status` | TEXT | 状态：issued(已发放)/voided(已作废) |
| `issue_date` | TEXT | 发放日期 |
| `generated_at` | TEXT | 生成时间 |
| `voided_at` | TEXT | 作废时间 |
| `void_reason` | TEXT | 作废原因 |
| `remark` | TEXT | 备注 |
| `operated_by` | TEXT | 操作人 |

#### 10.2.2 `certificate_batch_logs` 表（批量操作日志表）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | INTEGER PRIMARY KEY | 主键 |
| `course_id` | INTEGER | 关联课程ID |
| `operation_type` | TEXT | 操作类型 |
| `total_count` | INTEGER | 处理总数 |
| `success_count` | INTEGER | 成功数 |
| `failure_count` | INTEGER | 失败数 |
| `operated_by` | TEXT | 操作人 |
| `created_at` | TEXT | 创建时间 |

#### 10.2.3 `certificate_batch_items` 表（批量操作明细表）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | INTEGER PRIMARY KEY | 主键 |
| `batch_log_id` | INTEGER | 关联批量日志ID |
| `student_id` | INTEGER | 关联学员ID |
| `certificate_id` | INTEGER | 关联证书ID |
| `success` | INTEGER | 是否成功 |
| `failure_reason` | TEXT | 失败原因 |
| `created_at` | TEXT | 创建时间 |

### 10.3 生成条件校验规则

生成结业证书前必须满足以下全部条件，否则会被拦截并记录异常日志：

| 拦截场景 | 触发条件 | 失败原因 |
|-----------|----------|----------|
| 课程未结束 | 当前时间 < 课程结束时间 | 课程尚未结束，不能生成结业证书 |
| 学员未报名 | 学员不在课程报名名单中 | 该学员未报名此课程 |
| 已取消报名 | 学员报名状态为 cancelled | 该学员已取消报名 |
| 缺勤或出勤不达标 | 出勤状态不是 present | 该学员未出勤或出勤不达标 |
| 重复生成 | 该学员已有有效证书 | 该学员已有有效的结业证书 |

### 10.4 批量生成操作流程

1. **选择课程**：在结业证书管理页面选择已结束的课程
2. **预览名单**：系统自动筛选符合条件的学员，显示：
   - 符合条件学员列表（绿色）
   - 不符合条件学员列表及原因（红色）
   - 统计信息（总人数、符合条件、不符合条件）
3. **选择学员**：勾选要生成证书的学员（支持全选/取消全选）
4. **确认提交**：确认生成操作，系统逐条处理
5. **查看结果**：显示成功数、失败数及逐条失败原因
6. **导出结果**：可导出批量生成结果 CSV

### 10.5 证书补发

- 补发时会自动作废原有的有效证书
- 生成新的证书编号
- 记录补发操作到异常日志

### 10.6 证书作废

- 作废时必须填写原因（至少5个字符）
- 作废后证书状态变更为「已作废」
- 作废操作不可撤销
- 记录作废操作到异常日志

### 10.7 证书编号规则

证书编号格式：`CERT-{年份}-{课程简称}-{6位随机数}

示例：`CERT-2024-PYTHON-123456`

### 10.8 证书导出

导出的结业证书 CSV 包含以下内容：

**顶部统计信息：**
- 导出时间

**明细列：**
- 编号、证书编号、学员姓名、学员工号、部门
- 课程名称、课程主题、状态
- 发放日期、生成时间、作废时间
- 作废原因、备注、操作人

### 10.9 批量生成结果导出

导出的批量生成结果 CSV 包含：

**顶部统计信息：**
- 操作时间、课程名称
- 处理总数、成功数、失败数

**明细列：**
- 序号、证书编号、学员姓名、学员工号
- 处理结果（成功/失败）、失败原因、操作时间

### 10.10 数据持久化

- **结业证书**、**批量操作日志**、**批量操作明细**、**异常日志**全部写入 SQLite 数据库
- 关闭程序重启后，所有证书信息、状态、历史记录完全保持一致
- 所有操作（生成、补发、作废）均记录到 `exception_logs` 表，可追溯审计

### 10.11 常见问题

**Q: 如何进入结业证书管理？**
A: 点击左侧菜单「🎓 结业证书」即可进入管理页面。

**Q: 为什么有些课程不能生成证书？**
A: 只有**已结束**的课程才能生成结业证书。课程结束时间必须早于当前时间。

**Q: 缺勤的学员可以生成证书吗？**
A: 不可以。只有出勤状态为「已出勤」的学员才能生成结业证书。缺勤学员会被自动拦截。

**Q: 已取消报名的学员可以生成证书吗？**
A: 不可以。已取消报名的学员会被自动拦截。

**Q: 可以重复生成证书吗？**
A: 不可以。同一学员在同一课程中只能有一张有效的结业证书。重复生成会被自动拦截。

**Q: 补发证书后原证书还有效吗？**
A: 补发后原证书会被自动作废，状态变为「已作废」，只有新证书有效。

**Q: 作废的证书可以恢复吗？**
A: 不可以。作废操作不可撤销。如需恢复，可以使用补发功能生成新的有效证书。

**Q: 如何查看批量操作的历史记录？**
A: 在结业证书管理页面切换到「批量操作记录」标签页，可以查看所有批量生成记录，双击记录可以查看详细信息。

**Q: 导出的 CSV 文件在哪里？**
A: 导出目录是程序目录下的 `exports/` 文件夹，文件名包含时间戳。

## 11. 候补名单与自动补位

### 11.1 功能概述

候补名单模块允许管理员在课程满员时，将学员加入候补队列。当有学员取消报名释放名额时，可以一键执行自动补位，按优先级和加入时间顺序将候补学员转为正式报名。

### 11.2 数据库表结构

#### 11.2.1 `waiting_list` 表（候补队列表）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | INTEGER PRIMARY KEY | 主键 |
| `course_id` | INTEGER | 关联课程ID |
| `student_id` | INTEGER | 关联学员ID |
| `priority` | INTEGER | 优先级（0-100，数值越大越优先） |
| `source` | TEXT | 候补来源：manual/CSV导入/自动满员加入 |
| `status` | TEXT | 状态：waiting/processed/cancelled |
| `added_at` | TEXT | 添加时间 |
| `processed_at` | TEXT | 处理时间 |
| `note` | TEXT | 备注 |

### 11.3 候补添加方式

#### 11.3.1 手动添加

1. 进入「课程管理」，点击课程卡片进入**课程详情页**
2. 点击工具栏的「候补名单」按钮，打开候补管理对话框
3. 点击「添加候补」按钮
4. 填写学员信息（姓名、工号为必填项）
5. 可设置优先级（0-100，数值越大越先补位）
6. 点击「确定」完成添加

#### 11.3.2 CSV 批量导入

**CSV 文件格式（支持中英文表头）：**

|------|------|------|----------|--------|------|
| name | employee_id | department | phone | priority | note |

**导入步骤：**
1. 打开候补管理对话框，点击「导入候补」按钮
2. 选择准备好的 CSV 文件（UTF-8 编码）
3. 系统自动逐行校验并处理
4. 导入完成后显示结果统计：
   - 总行数
   - 成功添加数
   - 失败数及原因

### 9.4 候补排序规则

候补队列按以下规则排序，排序靠前的学员优先获得补位资格：

1. **优先级降序**：优先级数值越大，排名越靠前（默认 0）
2. **加入时间升序**：相同优先级的学员，先加入的排名靠前

### 9.5 自动补位操作

当有学员取消报名或课程容量扩容时，可执行自动补位：

1. 打开候补管理对话框
2. 查看「可用名额」和「候补人数」
3. 点击「自动补位」按钮
4. **预览阶段**：
   - 系统显示补位预览名单
   - 标注哪些学员可以成功补位，哪些会被拦截
   - 显示预计成功数和失败数
   - 如有注意事项（如报名即将截止等）会高亮显示
5. **确认执行**：
   - 确认无误后点击「确认执行补位」
   - 系统逐条处理候补学员
   - 符合条件的学员转为正式报名，占用课程容量
   - 不符合条件的学员会被拦截并记录失败原因
6. **结果展示**：
   - 显示补位统计：成功数、失败数
   - 显示每条记录的处理明细
   - 可点击「导出结果」导出补位结果 CSV

### 11.6 补位拦截规则

以下情况的学员在补位时会被自动拦截，并记录失败原因：

| 拦截场景 | 失败原因 |
|----------|----------|
| 已在报名名单中 | 学员已在该课程的报名名单中 |
| 课程未发布 | 课程状态为草稿，不允许补位 |
| 报名已截止 | 课程报名已截止，无法补位 |
| 容量不足 | 处理时无可用名额 |
| 已取消报名 | 学员曾报名但已取消 |

### 11.7 数据持久化

### 11.9 常见问题

**Q: 候补学员可以重复添加吗？**
A: 不可以。同一学员在同一课程中只能存在一条「等待中」的候补记录。系统会自动拦截重复添加。

**Q: 草稿课程可以添加候补吗？**
A: 不可以。只有状态为「已发布」的课程才允许添加候补和执行补位。

**Q: 报名截止后还能补位吗？**
A: 不可以。报名截止时间过后，添加候补和执行补位都会被拦截。

**Q: 补位执行过程中可以中途取消吗？**
A: 不可以。补位执行前有预览确认环节，确认后会完整执行。如需回滚，可手动取消新生成的报名。

**Q: 补位失败的学员还会留在候补队列吗？**
A: 取决于失败原因。对于非致命性错误（如暂时容量不足），学员会继续留在候补队列等待下次机会；对于已报名、已取消等致命错误，学员会被从候补队列中移除并标记为已处理。

**Q: 如何从候补队列中移除学员？**
A: 在候补管理对话框中，勾选要移除的学员，点击「移除选中」按钮即可。移除操作会记录到异常日志。

**Q: 候补学员补位成功后会收到通知吗？**
A: 目前系统为离线桌面应用，暂不支持自动通知。管理员可查看补位结果，手动通知相关学员。

**Q: 补位结果可以导出为 Excel 吗？**
A: 导出格式为 CSV（UTF-8 编码，兼容 Excel），可直接用 Excel 打开查看。
